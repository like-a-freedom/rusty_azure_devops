# Migration to `azure_devops_rust_api` as the single ADO backend

**Status:** completed. This is the record of a migration that has already
happened. The plan's remaining "planned" items were superseded by later
decisions, listed at the end.

## Goal

Make `azure_devops_rust_api` the only supported way to talk to Azure DevOps
across the repo, and remove the old hand-written HTTP client entirely. The
migration was breaking by design, with no fallback to the previous
implementation.

## Why

`azure_devops_rust_api` is an autogenerated SDK covering Work Item Tracking
(`wit`), Projects (`core::projects`), WIQL, and comments. It supports PAT
authentication through `Credential::from_pat` and exposes typed models such as
`JsonPatchOperation`, `WorkItem`, and `Comment`, which became the canonical
types behind the code and the schemas. Using it removes a large surface area of
hand-written HTTP and serialization code.

## What was done

1. The SDK is a required dependency, always enabled. The old feature flag was removed.
2. The previous HTTP client implementation and all of its tests and helpers are gone.
3. `AzureDevOpsClient` is implemented on top of the SDK. The core operations are covered by tests: list, create, get, and update work items, comments, WIQL, and retry behaviour.
4. Schema generation and validation derive from the SDK types, with thin wrappers where the SDK types lack `schemars` derives. `docs/schemas/` was refreshed to match the generated output.
5. Documentation states that the SDK is the only supported ADO backend, and the schema generation steps are documented.

## Superseded items

The plan listed several follow-ups that later decisions replaced rather than
completed as written:

- Replacing the hand-rolled DTOs with SDK types was overtaken by
  [ADR-0009](adr/0009-tool-surface-contract.md), which made the `Tool` enum
  the single source of truth for the tool surface.
- Error mapping landed as [ADR-0008](adr/0008-deepen-azure-error.md), which
  introduced the `AzureError` / `HttpError` pair instead of the conversion
  this plan sketched.
- The "tag a major version" step does not apply. The project is pre-1.0 and
  versions with minor bumps.

## Where things live now

| Area | Location |
|---|---|
| The client trait and the SDK adapter | `crates/azure_devops_client/src/` |
| API-version downgrade for on-prem servers | `crates/azure_devops_client/src/api_version_policy.rs` |
| The direct HTTP fallback for on-prem quirks | `crates/azure_devops_client/src/resilience.rs` |
| The test double | `crates/azure_devops_client/src/in_memory_client.rs` |
| Generated tool contracts | `docs/schemas/` |
